# AGENTS.md

Guidance for AI coding agents working in this repository.

## Stack

- Classic Lua **World of Warcraft addon** built on **Ace3** (`AceAddon-3.0`, `AceConsole-3.0`, `AceEvent-3.0`), loaded via `HiddenLodge.toc`. There is no build step — WoW loads the `.lua` files listed in the `.toc`, in order, directly from the addon folder.
- No package manager, no bundler, no tests. "Running" the addon means installing/symlinking this folder into a WoW `AddOns` directory and using `/reload` in-game (see README's Build and workflow section).
- Persistence is a single per-account saved variable, `HiddenLodgeDB` (declared via `## SavedVariables` in the `.toc`), exposed on the addon object as `self.db`. It only survives to disk on logout/reload — there's no other storage.
- A separate companion app, `HiddenLodgeDesktop` (different repo), pushes synced data (Preparedness, Attendance, Great Vault, Droptimizer, alt-note mappings) into `HiddenLodgeDB` outside the game client; this addon only reads that data. Raid Comp is the one panel that's filled by pasting a string copied from the website instead — see below.
- The companion website, `HiddenLodgeWebsite` (different repo, `../HiddenLodgeWebsite`), is the other end of two integrations: `/raid-composition`'s "Export to Addon" button (consumed by `HiddenLodge_RaidComp.lua`) and whatever the Desktop app syncs. Check that repo's `AGENTS.md`/`src/lib/raid-comp.ts` before changing the export string format or field meanings on either side — they must stay in lockstep.

## Conventions

- **File layout**: one `HiddenLodge_<Feature>.lua` file per feature/panel (Preparedness, GreatVault, Attendance, RaidSignup, Droptimizer, InviteTool, RaidComp, AltNoteSync, CauldronTracker, Integration_RCLootCouncil), plus `HiddenLodge.lua` (Ace3 bootstrap, saved-variable defaults, slash command routing, integration registry), `HiddenLodge_Style.lua` (shared UI constants/colors and button style helpers), and `HiddenLodge_UI.lua` (main window + buttons that open the other panels' frames). New files must be added to the `.toc`'s load list (order matters: a file that calls `HiddenLodge:GetUIConstants()` or other helpers needs those defined first) and to README's file list.
- **Module pattern**: every file opens with `local addonName = ...` then `local HiddenLodge = LibStub("AceAddon-3.0"):GetAddon(addonName)`, and attaches its functions as methods on that shared `HiddenLodge` table (`function HiddenLodge:DoThing() ... end`). There's no per-module namespace — everything lives on one addon object, so pick distinctive function names to avoid collisions across files.
- **Saved variable defaults**: `HiddenLodge.lua`'s `ensureDefaults(db)` is the single place that initializes every `db.<feature>` subtable with `db.x = db.x or {}` guards. A new feature that persists data adds its block there, not ad hoc in its own file (Raid Comp is the one exception — its `self.db.raidComp` is populated straight from a pasted string, not defaulted here, since it's meant to go stale and be re-imported before every pull).
- **Slash commands**: routed centrally through `HiddenLodge:HandleSlashCommand` in `HiddenLodge.lua` (`/hl [show|hide|cauldron|raidcomp]`). A new panel that should open by chat command adds a branch there guarded by `if self.ShowXFrame then`, and the panel file defines `ShowXFrame`/`ToggleXFrame` itself — `HiddenLodge.lua` never assumes a panel file is loaded.
- **Name/realm matching**: every feature that cross-references a WoW unit/character against synced or pasted data normalizes with the same `trim`/`normalizeName`/`normalizeRealm`/`normalizedFullKey` pattern (strip whitespace, lowercase, strip spaces/hyphens/apostrophes from the realm) and matches full key first, falling back to name-only. This helper is duplicated per-file (`HiddenLodge_InviteTool.lua`, `HiddenLodge_RaidComp.lua`, etc.) rather than shared — keep new copies byte-for-byte consistent with the existing ones rather than "improving" one in isolation, since a mismatch between files would silently break cross-referencing.
- **Permission checks**: any action that mutates the raid (invite, subgroup move, mass whisper) checks raid leader/assistant status before acting (see `canOrganizeRaid()` in `HiddenLodge_RaidComp.lua`, `canInviteToCurrentGroup()` in `HiddenLodge_InviteTool.lua`) and reports failure via `self:SetStatus(...)` rather than erroring silently.
- **Status/feedback**: `HiddenLodge:SetStatus(message, r, g, b)` (in `HiddenLodge_UI.lua`) is the shared way to surface a result or error on the main window — green-ish for success, amber for partial/warning, red for failure. Panels use it after every mutating action (import, invite, organize, whisper) rather than rolling their own text popups.
- **UI construction**: panel frames are hand-built with `CreateFrame` + `BackdropTemplate`, styled from `HiddenLodge:GetUIConstants()` (`HiddenLodge_Style.lua`) with a fallback literal if constants aren't available, and follow the same skeleton every time — outer frame → header bar with title/close button → content panel → row list backed by a pooled-row scroll frame (see `getRaidCompRow`/`raidCompRowPool` in `HiddenLodge_RaidComp.lua` for the pooling pattern: reuse row frames by index instead of creating/destroying them). Match this skeleton for new panels rather than introducing a different frame-building style.
- **Mass actions that touch real players** (inviting many people, moving subgroups, sending whispers) are confirmed or at least clearly reported — see `StaticPopupDialogs["HIDDENLODGE_WHISPER_DOWNSIZE_CUTS"]` in `HiddenLodge_RaidComp.lua` for the confirm-dialog pattern (`StaticPopup_Show(key, textArg, nil, data)`, read back via `self.data` in `OnAccept`). Don't fire this kind of action straight off a button click without at least a status-line summary of what happened (invited/failed counts, etc.).
- **Chat/whisper sends**: use `C_ChatInfo.SendChatMessage`, not the deprecated global `SendChatMessage`.
- **Integrations** (currently just RCLootCouncil): registered via `HiddenLodge:RegisterIntegration(name, { addon = "OtherAddonName", init = function(self) ... end })` in the integration's own file, then initialized automatically once both Ace3 confirms `OtherAddonName` is loaded and `ADDON_LOADED` fires (or immediately at `OnEnable` if it's already loaded). Don't call integration setup code directly at file scope — always go through this registry so load-order races (addon loads before/after HiddenLodge) are handled uniformly.

## Commands

There is no build/lint/test command. The only "workflow" is:
1. Symlink or copy this folder into `_retail_/Interface/AddOns/HiddenLodge`.
2. `/reload` in-game after any `.lua` change.
3. `/hl` to confirm the addon loaded; watch for Lua errors (enable `/console scriptErrors 1` or an error-catching addon like BugSack while testing).

## Notes

- **Release automation**: `.github/workflows/release.yml` uses `BigWigsMods/packager` to package and publish to CurseForge on tag push (`v*`), reading project id from `.pkgmeta`. Bumping the version means updating `## Version` in `HiddenLodge.toc` and pushing a matching tag — there's no separate version file.
- **Raid Comp export/import contract**: the website's "Export to Addon" button on `/raid-composition` produces `HLRC1|Name-Realm:Group:CLASSTOKEN,...` (realm stripped of spaces/hyphens/apostrophes so `-` unambiguously separates name from realm; a temp/PUG candidate has no realm and is bare `Name:Group:CLASSTOKEN`). `HiddenLodge_RaidComp.lua`'s `ParseRaidCompImportString`/`ImportRaidCompString` parse it into `self.db.raidComp.entries` on paste — this is deliberately not desktop-synced, since the comp needs to be current right before pulling, not stale from the last `/reload`. Three actions read that imported state: **Invite Missing** (invite anyone in the comp not yet in raid, reusing `HiddenLodge_InviteTool.lua`'s invite logic), **Organize Groups** (best-effort subgroup moves for a raid leader/assistant, one pass per click), and **Whisper Cuts** (whispers everyone currently in the raid who *isn't* in the imported comp, telling them to drop for downsizing and pointing at the website's Raid Composition page — also raid leader/assistant only, confirmed via a `StaticPopupDialogs` count prompt before sending). If the export string format changes on the website side, `ParseRaidCompImportString` needs a matching update here.
- **Cauldron tracker** detection is best-effort and layered: a known-spell-id cast start, a name-contains-"cauldron" fallback, and a burst-detection fallback (3+ different players creating flasks/phials within 30s) if the placement cast itself was missed. Don't assume the primary detection path is reliable enough to drop the fallbacks.
- **Ace3 is a soft dependency**: `HiddenLodge.lua` checks `LibStub and LibStub("AceAddon-3.0", true)` at file scope and prints a chat warning instead of erroring if Ace3 isn't installed. Don't add code elsewhere that assumes Ace3/LibStub exist without going through this same guarded pattern.
